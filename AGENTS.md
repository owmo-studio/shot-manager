# OWMO Shot Manager — agent guidance

## Purpose and scope

OWMO Shot Manager is a single-user, local macOS Electron app for reviewing original video footage from cards and folders, editing per-shot attributes, and processing selected footage into a canonical NAS Library. Processing encompasses destination placement, associated assets, metadata, and required transformations; the implementation prepares local ProRes proxies, transfers originals/thumbnails/missing proxies, and publishes JSON last. It manages an active working library, not an archive.

Validate Import and the basic Library view using isolated dummy sources and destinations. Resolve importing/plugins, expanded search/filtering, and deletion remain deferred; discuss their details before implementation.

Read the relevant code and `README.md` for current behavior. Treat this file as durable constraints, not a complete product specification. If older documentation conflicts with working code or a new user instruction, resolve the discrepancy before changing behavior.

## Non-negotiable safety

- Source footage is read-only. Never rename, delete, overwrite, transcode, or reorganize original media as part of discovery, inspection, or testing.
- Never read, write, or mutate real NAS media during prototyping without explicit authorization for that operation. Use temporary dummy folders and synthetic media in automated tests. A configured Library path alone does not authorize NAS access.
- Before any future Library write, validate the configured destination and mounted volume. A missing SMB mount must never turn into a write to its empty local mount-point directory. Do not use example paths as defaults.
- Preserve corrupt or unreadable persisted state and report the error; do not silently replace it. Keep destructive local-data operations explicitly confirmed and confined to recognized app-owned files.
- Backend filesystem routes accept validated asset identifiers, never arbitrary renderer-supplied paths. Keep Electron's preload restricted and the backend bound to authenticated loopback access.

## Architecture and data

- Keep the existing Electron/electron-vite, React/TypeScript, Fastify, and `shared/` structure. The backend runs as a separate Electron utility process; renderer reloads must not own or cancel backend jobs. Avoid new services, databases, or dependencies without a concrete need.
- Inspect each original video independently. Source-derived technical metadata is read-only; unknown or conflicting values remain explicit. Do not infer device, codec, color, or capture date from folder names, camera proxies, or external XML. Playback and previews use originals; cached thumbnails are disposable.
- All assigned attributes (Identity, Project, Scene, Group, Camera, Rating, Notes, and Tags) are optional, including when processing clips. Persist Identity/Project options; keep Tag suggestions as a session-only list of tags used by loaded clips while preserving tags in clip drafts. Keep editing selection distinct from the current skip state: discovered clips are included by default, and an explicit skip excludes them from future processing and persists in the fingerprint-keyed local draft. Clearing attributes preserves Skip. Do not reintroduce a separate processing checkbox. See the code and `README.md` for interaction details.
- Library choices in Configuration remain pending until Save. Cancel, close, and Escape discard pending choices. Cache storage is app-managed under the local app data directory; there is no Cache location setting.
- Configuration Identity/Project deletions clear only the matching field and cascade to all saved local clip drafts, including offline records, after an affected-clip review distinguishing active and saved records. Unused entries need no extra confirmation. Apply atomically, preserve unrelated attributes, reject stale reviews/scan conflicts, and update loaded clips without rescanning. This does not authorize changes to source footage or Library files.
- After confirmation, Revert restores the descriptive attributes and thumbnail from selected pending clips’ validated Library assets into local Cache/drafts as a batch. Preserve Skip and processing receipts; reject missing, invalid, mismatched, or symlink assets and concurrent local edits without partial restoration. Stage thumbnails with rollback backups until the draft save succeeds. This explicit action reads only selected metadata/thumbnail files and never writes Library assets.
- Local drafts, configuration, fingerprint records, and disposable previews have different reset semantics. `Clear Cache` confirms selective deletion of app-owned catalogue, metadata, thumbnails, fingerprints, and proxies, with keep checkboxes for each category. It preserves the saved Library location, source footage, and Library assets. Browse Cache opens the app-managed folder in Finder. The Library location X stages clearing its setting for Save. Previous user-chosen Cache files are preserved when switching to app-managed storage; do not delete them automatically. After 90 days without use, clip drafts (including synced receipts), thumbnails, valid fingerprint records, and cache proxies expire during graceful shutdown. Saved Identity/Project options and corrupt persisted records remain until explicit clearing. Clearing selected clips' attributes or removing vocabulary entries has narrower effects.
- Publish clips only after fingerprint and attributes are ready; use the fingerprint as the clip ID across selection, editing, and asset lookup. Keep file locations separate. The backend workspace owns one record per fingerprint with one active absolute file path/identity; scan jobs do not own clip records or thumbnail lifetimes. Repeated/overlapping discovery keeps a valid active path and current edits, or adopts a freshly fingerprinted matching copy when the old path is unavailable. Never switch a queued Commit’s captured path before completion/cancellation. Discovery requests carry only an ID/path; no retained Source registry or source-mutation API remains.
- A sampled fingerprint associates local drafts/previews with matching media and is the Library ID; it is not proof of duplicate content or transfer integrity. Successful rsync completion is the accepted transfer-success criterion; do not add a separate full-file SHA-256 pass.

## Agreed Library storage

- Start with a flat Library: `<full-lowercase-sampled-fingerprint>.<role>.<ext>`. Reserved roles are `source`, `thumb`, `metadata`, and `proxy`, with one published asset per role per shot initially. Preserve the source's original format extension, normalized to lowercase; generated assets use their actual format's extension. Preserve the original source filename in metadata JSON.
- Processing places a copy of the original video, the current generated or assigned thumbnail, a ProRes proxy if missing, and metadata JSON in the Library. Always include every attribute field, even when empty: `identity: null`, `project: null`, `scene: ""`, `group: ""`, `camera: ""`, `rating: null`, `notes: ""`, and `tags: []`. The JSON also preserves source/technical metadata, date evidence/confidence, and processing completion information; see `README.md` and the implementation for the field contract.
- The app generates ProRes 422 Proxy MOV files; other software may add derived assets. Discover optional assets by fingerprint and role; no separate asset-inventory manifest or centralized database is required. Keep the internal contract simple; schema versioning and multi-writer coordination machinery are not required. Assume existing regular Library proxy filenames are good; leave them and other additional assets untouched during processing.
- Readers ignore temporary/partial filenames. Let rsync use its temporary-file-and-rename behavior; do not expose an in-progress transfer under its final filename. Publish metadata JSON atomically and last, after source, thumbnail, and any missing proxy transfers succeed. Existing JSON during a replacement describes the previous completed version until replaced.
- Library uses a disposable local catalogue (`catalogue.json`) separate from shared fingerprint-keyed drafts. Entering Library shows cached rows, then pulls current JSON with at most four concurrent readers; explicit Refresh and metadata Commit review also pull current data. Preserve pending edits, unreadable records, and the last usable catalogue while offline. Clean rows follow remote metadata; differences stay yellow with Commit/Revert and no conflict workflow. The existing JSON/name contract is in `shared/library.ts`. Load thumbnails/playback on demand; never run Import discovery, FFprobe, or encoding for catalogue rows. Keep paths centralized; defer buckets until measured SMB performance warrants them.
- Both tabs share the grid, inspector, and device filters, but retain separate filters/selections. Library cards are neutral unless changed/queued, with no Skip/Eject actions. Thumb stages a local image shared by fingerprint; Commit uses the shared worker, rsyncs a changed thumbnail, then publishes JSON last while preserving technical/extra fields and source/proxy assets. Revert restores selected current JSON and thumbnails as a staged local batch. Successful Import publication updates the catalogue and removes that workspace clip; rediscovery can show green. With no editing selection, Import Commit review includes green Synced rows for workspace removal; only included rows are cleared after confirmation, preserving files/drafts/receipts. Cancel/exclusion and selected-only Commits keep green cards. Catalogue and pending edits can be cleared independently in Configuration. Library Export reviews the explicit selection, permits X/dash exclusion/restoration, and requires included clips to have no pending edits. Export uses a native-picked destination capability and the shared transfer worker. The Resolve formatter names sources `<original-stem>__<fingerprint-prefix>.<ext>` directly in that folder, with matching `Proxy/*.mov` and a dated per-batch CSV in `Metadata/`; do not export per-clip app JSON. Sanitize unsafe filenames, extend fingerprint prefixes on collisions, and reuse established names by checking existing exported sources with the sampled fingerprint. CSV rows describe successfully exported clips only; optional attributes remain blank. Keep editor formatting separate from guarded transfers, with reviewed replacement and mount/file/directory identity checks. Never write inside the Library or overwrite original footage; Export leaves Library assets/receipts unchanged. Resolve importing/plugins and Delete remain deferred.

## Agreed processing queue

- Eligible clips are not skipped, already queued, or synced in their current state. Each must have an available source video and a ready generated or assigned thumbnail; missing attributes do not block processing. Enable Commit when the candidate list is nonempty and ready. Validate the configured Library destination and mount before execution.
- Commit targets eligible selected clips when any clips are selected; with no selection it targets all eligible workspace clips. Skip remains persistent and excludes clips in either scope. A selection containing no eligible clips disables Commit without falling back to all clips. The footer identifies selected scope and eligible count. Commit opens a simple confirmation with count, total size, and a scrollable clip list marked New or Update. New/Update tags are neutral blue; reviewed Synced removals are green. Proxy preparation is implicit. An X excludes and dims a row in this submission, then changes to a dash that restores it when clicked; excluded rows remain visible and saved Skip is unchanged. Cancel makes no queue changes; Commit authorizes queueing and replacement for the included rows. Detect existing fingerprint matches during review and recheck before writing; a newly discovered conflict requires a decision rather than an unreviewed overwrite.
- Capture an immutable in-memory snapshot of each accepted clip's source, thumbnail, attributes, and destination. Lock waiting and processing clips against edits and execute from the snapshot. Folder discovery may continue during Commit. Per-clip Stop removes selected queued/active Commit snapshots while retaining workspace clips and unrelated work; Commit remains available for new eligible clips and appends separately reviewed immutable snapshots to the same transfer worker. Use one transfer worker and one independent proxy encoder concurrently. Choose queued Exports before queued Commits, preserving order within each priority; never interrupt an active transfer for priority. Submitted clips get encoding priority. When another submitted clip needs encoding, interrupt an unsubmitted encode strictly below 20%, clean its partial output, and restart it later; never preempt a submitted or finishing encode. Ready clips transfer without waiting behind clips still encoding. Backend work survives renderer reloads. Internal byte-weighted source/thumbnail/proxy transfer progress stays below 100% until metadata publication, receipt persistence, and completion cleanup succeed.
- The footer application indicator reports one highest-priority issue (red for configuration/communication failures or an unavailable Library, yellow for unavailable media or proxy work), newest among equal priorities, or green Ready only after successful checks. Its lightweight health checks may inspect the configured Library folder/mount and permissions; do not poll asset inventories or open media. Cache errors surface through background work, not a configured-location check.
- Adding folders through buttons or drag and drop is unavailable while the application indicator reports a critical (red) issue such as Library Not Set. The empty workspace reflects that issue rather than claiming readiness. Yellow warnings do not by themselves block adding sources.
- The footer always shows Proxies, Commits, and Exports in fixed positions, with white active counts and dimmed idle counts. Both tabs share these counts and active percentages through one notification subscription; tab switches do not reload queue status. Counts show unfinished clips, including active work, without totals. The Proxy bar shows the current encode; Commits and Exports share a green bar for the current transfer, with its active label highlighted. Per-card progress provides detail; there is no combined aggregate bar. Backend task accounting retains completed history during a session, adds new work, and removes cancelled/skipped/failed unfinished tasks. Footer Stop leaves thumbnails running. Card style communicates Discover/Editable/Queued/Active/Synced/Change: discovery is locked until thumbnail preparation completes, background encoding alone never locks metadata, queued cards dim and subtly animate, active transfers show a centered spinner, synced cards have prominent green backgrounds and changed cards yellow backgrounds, with matching green/yellow outlines only when selected. Skipped cards are nearly black with heavily darkened thumbnails and muted filenames, but remain editable. Other card states need no visible badges/text. The undimmed top-left proxy indicator is hollow white until a known location, yellow in Cache, green in Library, including for Skip, with explanatory hover/accessibility text. Active encoding and transfer use matching 6px yellow/green spinners without backdrops and gently darkened thumbnails; transfers take precedence. The thumbnail progress bar is yellow for proxy encoding and green for Library sync, without visible numbers; transfer activity takes precedence. Encoding/Commit overlays preserve the base card state, including queued locks, selection, and Library state; work contrast must not reset base opacity or grayscale.
- Use rsync for the source, thumbnail, and missing proxy. Preserve source modification times and use rsync's size/mtime quick check to avoid recopying unchanged files; existence alone is insufficient. Metadata-only changes should update JSON without recopying unchanged video. A successful transfer followed by successful JSON publication completes processing.
- Persist the last successful processing state alongside the fingerprint-keyed local draft, including the Library destination and the attributes/thumbnail state needed to recognize changes. Show Synced for a clip matching its last successful processing state and exclude it from subsequent submissions. Attribute or thumbnail changes show Needs Syncing and make it eligible again; Skip and editing selection do not invalidate sync state. Recognize reverted edits when they match the last successful state. Check Library asset filenames on startup, destination changes, before review, and explicit refresh, without polling asset listings or opening media/JSON contents. Synced requires the source, thumbnail, metadata JSON, and proxy to be present. Missing assets make the clip eligible again; a fully deleted clip is New. Existing core Library assets without a matching receipt, or with an incomplete asset set, show Needs Syncing and are reviewed as Update; genuinely new clips remain neutral. Preserve receipts and show unverified status if the Library cannot be checked; never treat an unavailable share as empty. This presence check does not verify file contents.
- The footer work control is Refresh when idle/paused and a spinner while transfer or background work exists; hover or keyboard focus reveals a red Stop square. Refresh checks Library/cache presence and resumes missing thumbnail/proxy generation only; cancelled Library submissions require Commit again. Stop confirms before cancelling proxy encoding and rsync, clearing Commit/Export queues, and suspending automatic proxy generation. Thumbnail generation continues, including for newly discovered clips; only shutdown, Cache clearing, and clip lifecycle actions settle or cancel thumbnail jobs. A late refresh completion must not restart stopped work. Commit refreshes Library/cache presence and resumes required preparation before review, with transfers starting only after confirmation. A late Commit review must not restart work after Stop. Footer Stop cancels proxies, Commits, and Exports; inspector Stop cancels only selected Commits. Completed Library clips, prior receipts, pending changes, and completed cache proxies survive cancellation. Keep both footer bars visible but empty when idle. Never mark cancelled work synced; Library orphan cleanup remains deferred.
- Cache is managed under the local app data directory in a `Shot Manager Cache` folder with category subfolders, beside Electron's own `Cache` folder. It is not a user-configured or monitored location. Start the new Cache empty; leave files in the former shared `Cache`, older `owmo-shot-manager`, and previously user-chosen locations untouched. Generate only missing proxies after the Library filename check; reuse completed cache proxies by fingerprint. Use ProRes 422 Proxy MOV, 10-bit 4:2:2, 1280-pixel maximum long edge without upscaling, preserved display aspect/orientation, locked frame timing/timecode and audio channelization. Do not bake viewing LUTs or invent color declarations; camera-specific color evidence stays in JSON. Limit encoding to one lower-priority worker behind thumbnail preparation. Publish cache outputs by rename only on success, guard free space and folder identity, and delete matching cache proxies only after successful Library publication and local receipt persistence. No quota, database, or durable proxy journal is required. Clear Cache preserves whichever app-owned categories the user selects to keep.
- On failure, show a dialog identifying the clip and available error details, remove and unlock that entry, and continue the remaining queue. Preserve any previous successful processing record. Retained failed entries, retry workflows, and orphan cleanup are deferred.
- The queue is not persisted. An application crash or restart discards unfinished queue work; no durable journal, automatic resume, or recovery workflow is required. Usual local draft persistence and successful-processing state survive. A renderer reload is not an application restart and must not cancel backend work.
- Use dry-run plans and fault tests on dummy folders before requesting authorization for any real NAS write.

## Workspace lifecycle

- The left panel has an All filter with total clip count and device filters. All is a neutral reset action that clears filters. Device rows toggle by clicking anywhere and show a checkmark when selected. Folder and dropped video-file requests discover additively, even during Commit; file drops inspect only the requested supported video files, never sibling clips, with temporary scan feedback above the grid. Duplicate discoveries retain the healthy active path; unavailable paths may be replaced by a freshly fingerprinted copy. Discovery never owns membership or locks existing clips.
- Inspector Stop confirms the affected clip list, then retains selected queued/active clips and unlocks them after cancellation settles; proxy preparation continues. Eject confirms the selected clips before removing unqueued clips and settling their background work, preserving originals, Library assets, drafts/Skip, receipts, and completed cache proxies. Mixed selections first stop only queued/active Commits. Backend guards prevent stale UI from ejecting newly queued clips. Successful publication racing cancellation retains its receipt.
- Eject exclusions prevent late callbacks from restoring removed cards; explicit later folder addition may restore them. Clear Cache hands surviving paths, unfinished scans, and exclusions across its backend restart without rescanning completed roots. Workspace membership and queues remain session-only.
- Monitor only unique actual clip-containing directories for existence; stop when unreferenced. Missing directories flag affected clips and show one path/count warning per outage. Preserve offline edits; recovery revalidates individual files and respects manual Stop. File access validates the same size/mtime/ctime/filesystem identity used by fingerprint caching; a changed file needs fresh discovery even if its size/mtime match. Unavailable queued clips fail/unlock while others continue; Commit again after recovery.
- Append reviewed Commits without resetting active transfers or progress history. Serialize review/submission validation, not the worker; reject stale snapshots/new conflicts without disturbing earlier submissions. A draining worker waits for in-flight submission validation. Lost append responses check submitted clips rather than infer success from unrelated work. Footer Stop also cancels submissions being validated.

## Working in this repository

- Find current implementation details in `README.md` and the adjacent code. Keep changes focused; update documentation when behavior changes. Confirmations use a clear action question, a brief impact description, and optional useful subtext; shared button styles use blue for primary actions, red for destructive confirmations, and grey for Cancel/Dismiss.
