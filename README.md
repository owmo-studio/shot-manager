# OWMO Shot Manager

OWMO Shot Manager is a local macOS desktop app for browsing original video footage from cards and folders, inspecting clips, and assigning per-shot attributes. Commit places clips, proxies, thumbnails, and metadata in the Library. The current Import workflow prepares ProRes proxies in app-managed cache storage, copies original footage, thumbnails, and missing proxies into the canonical Library, and publishes metadata through a reviewed transfer queue. Development validation uses isolated dummy sources and local destinations; real NAS validation remains pending.

## Requirements

- macOS, Node.js 22.12+, and npm
- macOS bundled `/usr/bin/rsync` (or compatible openrsync)
- FFmpeg and FFprobe available on `PATH`, with the `prores_ks` encoder and the scale filter’s `reset_sar` option

## Run locally

```sh
npm install
npm run dev
```

Viewing LUTs are included in the repository. See [LUT provenance](resources/luts/README.md). `npm run build` checks TypeScript and creates `out/` with the LUTs; `npm start` opens that build. This repository does not currently produce an installable app.

## Current functionality

- Add multiple card or folder sources, browse original videos by recording date, filter by device, inspect technical metadata, and play or seek the original video. Clips appear after fingerprinting and attribute loading; their identity follows the fingerprint across moves and rescans. The backend workspace holds one record per fingerprint and one active absolute file path per clip. Repeated or overlapping additions retain an existing valid path and its state; a freshly fingerprinted matching copy replaces an unavailable path. A queued Commit keeps its captured path until completion or cancellation. Adding a folder again performs additive discovery without resetting existing cards. The left panel contains All (with total clip count) and per-clip device filters; All clears active filters; folder scanning appears as temporary progress above the grid. There is no Source list, source filtering, source rescan/remove control, or Devices heading. The backend queues thumbnail generation for every identified clip during scanning, independently of card visibility or renderer reloads, using one worker and reusing cached/custom previews. Scanning continues while thumbnails are pending; preview failures do not prevent clips appearing. The grid loads cached images as cards approach the viewport. Camera proxies, thumbnails, and external XML are not used.
- Add folders through + or drag and drop, or drop individual supported video files, including while other clips are committing. File drops inspect only those files; non-video extensions are rejected. Adding is disabled for critical red application issues such as Library Not Set; the empty workspace reflects that issue. Yellow warnings do not block discovery.
- Edit Identity, Project, Scene, Group, Camera, Quality, Notes, and Tags per clip. All assigned attributes are optional, including when processing clips. Attributes and Skip choices persist locally; workspace membership and editing selections are session-only. Successful processing receipts persist with local drafts. Skipping a clip is separate from selecting it for inspection.
- Use Eject in the inspector for a single or multiple selection; thumbnails have no Eject/Stop buttons. Eject asks for confirmation, then removes workspace membership and cancels only those clips’ unfinished jobs. Queued/active Commits show Stop (outlined square) instead of Eject. Stop confirms the affected clip list, then cancels only the selected Commit snapshots, keeps their clips selected in the workspace, and unlocks them after the transfer settles. Background proxy encoding continues independently. A subsequent click offers Eject (triangle/bar). In mixed selections, Stop affects only queued/active clips and preserves all membership. Selected queued/active cards have a clear light outline. Original footage, Library assets, cached metadata/Skip, receipts, and completed proxies are preserved. Ejected clips are excluded from late scan results; explicitly adding their folder again can restore them.
- Use the LUT toggle over the video's top-left corner to review supported Sony S-Log3 and Apple Log footage. Viewing transforms and cached previews do not change source files. Thumbnail, Skip (circle-minus, neutral active style), and Eject sit in that order as icon-only actions in the Import inspector header, with hover labels.
- Set a Library location in Configuration. The app checks the mounted destination and lists its asset filenames on startup, after saving the location, and before processing review. This presence check does not open media or JSON contents or write to the Library. **Commit** confirms an explicit clip list before queueing transfers. See the processing behavior below.

Configuration shows total Cache space used, with a compact Proxies/Thumbnails/Metadata size breakdown. **Clear Cache** confirms which app-owned Cache files to delete. Check **Keep Library catalogue**, **Keep metadata**, **Keep thumbnails**, **Keep fingerprints**, or **Keep proxies** to retain those categories; unchecked categories are cleared. Metadata includes local clip attributes, thumbnail choices, Identity/Project lists, and commit receipts. The workspace reloads after clearing, restoring exact surviving file paths and unfinished discovery with Eject exclusions. Completed folder roots are not rescanned, so ejected sibling clips stay out. This is an in-memory handoff during Clear Cache, not a persisted queue or crash-recovery journal. Source videos, Library assets, and the saved Library location remain untouched. **Browse Cache** opens the app-managed `Shot Manager Cache` folder in Finder. A small X beside the Library location stages clearing that setting for Save.

The inspector orders fields as **Identity → Project → Scene → Group / Camera / Quality → Notes → Tags**. Clear and Revert sit at the bottom-left of the attributes panel, with the Saving status aligned right on the same row for single and multiple selections. Clear is disabled when all descriptive attributes are empty across the selected clips; Skip alone does not enable it. Revert is enabled for selected clips with pending updates and requires confirmation before replacing their local attributes and thumbnails with the current Library values. In a mixed selection it applies only to clips with pending updates. It reads only the selected metadata and thumbnail files on demand after validating the configured Library volume; normal presence scans still read filenames only. It preserves Skip and processing receipts. Missing Library assets may still need processing. Missing, invalid, or symlink Library metadata/thumbnails reject the whole selection; failed draft saves roll back staged thumbnails; successful restores refresh the inspector immediately and retain restored Identity/Project options. Scene is an optional short sentence, saved with each clip like Notes, with no suggestion list. It allows up to 80 characters: Unicode letters and numbers, spaces, apostrophes, commas, periods, and hyphens. Curly apostrophes and long dashes normalize to plain punctuation; extra spaces are collapsed. Group and Camera are optional text (up to 128 characters); Quality is blank, Preferred, or Usable. They share a 50/25/25 row in both tabs and support bulk editing. Notes has a two-line editor, and the default window keeps all attribute fields visible. Widening the right panel enlarges the video preview proportionally, with the original image aspect ratio preserved. The character policy does not affect fingerprint-based Library filenames.

Identity and Project options persist; Tag suggestions reflect tags used by currently loaded clips, while clip tags remain saved in drafts. Removing Identity or Project options in Configuration clears only the matching field across local clip records. **Save** shows an affected-clip count and table distinguishing active and saved clips before confirmation; unused entries are deleted directly. No rescan is triggered. Other attributes stay intact. Removal waits for active scans to finish; changed attributes require a fresh review. Older saved records without a filename show a clip identifier until scanned again.

Unreadable or invalid saved drafts, configuration, and fingerprint records are preserved and reported. A clip whose fingerprint or draft cannot be loaded is skipped during discovery; discovery issues appear in the scan summary. Clear Cache remains an explicitly confirmed operation.

Failed clip edits remain in the main process for the current app session, including across inspector changes and renderer reloads. An app-level banner offers retry; later edits wait behind failed edits so retry preserves their order. Source changes, option removals, and reset wait for successful saves. The window close button and Command+Q use the same exit path: finish accepted edits, stop the backend, then close the window. The window displays shutdown progress while background work stops; failed saves offer Keep Working, Retry Saves, or an explicit Quit Without Saving. Retained unsaved edits are in memory, not a crash-recovery journal.

Clip fingerprints use `sampled-sha256-v2`: file size, the fixed sampling scheme and byte ranges, and bytes read from the original file. Large files use five 256 KiB samples spread from the start to the end; files up to 1.25 MiB are read in full. Extracted metadata, paths, and filesystem dates do not contribute to clip identity. Filesystem details only invalidate cached reads and detect changes during inspection. A sampled fingerprint associates local drafts and previews; it does not prove duplicate content or transfer integrity. Processing accepts successful rsync completion without a separate full-file SHA-256 pass. Rsync uses size and modification time to skip unchanged destination files; this is not independent verification of stored destination bytes. This development change does not migrate earlier fingerprint records or their associated drafts/previews.

The footer’s single application indicator shows **Ready** in green after successful checks; red indicates missing/invalid or unavailable Library storage, or communication failure, and yellow indicates unavailable media or proxy preparation. Only the highest-priority message appears, with the newest report winning among equal priorities; hover for details. Startup checks retry quickly until the backend connects; the normal five-second health cycle then checks the configured Library folder/mount without listing Library assets or opening media. A backend startup failure shows Backend Unavailable rather than leaving Starting on screen. The app-managed Cache is not a monitored location; proxy preparation reports its own errors. Slow checks remain yellow rather than reporting a false Ready state. Saving configuration requests an immediate status refresh. Existing detailed dialogs remain available.

## Library and processing

The Library is flat. Asset filenames are `<full-lowercase-sampled-fingerprint>.<role>.<ext>`:

```text
<id>.source.mp4
<id>.thumb.jpg
<id>.metadata.json
<id>.proxy.mov       # ProRes 422 Proxy
```

Sources retain their original format extension, normalized to lowercase. Processing copies the original video, current generated or custom thumbnail, and a missing proxy with rsync, then atomically publishes metadata JSON last. Existing Library proxies are assumed good and retained without content inspection or replacement. Other tools can discover additional assets using the ID and role; other additional assets remain untouched. Temporary and partial filenames are not published assets. Bucket directories, a shared database, and asset-inventory manifests are not used.

The metadata JSON contains `id`, `fingerprint` (including its sampling scheme), `originalFilename`, `bytes`, `recordedAt`, `dateSource`, `dateEvidence`, `dateConfidence`, `durationSeconds`, `metadata` (the existing technical metadata structure), `warnings`, and `ingestion: { completedAt, transfer: "rsync" }` (the existing stored field for processing completion). It always includes all assigned attributes: `identity` and `project` are strings or `null`, `scene`, `group`, `camera`, and `notes` are strings (including `""`), `rating` is `"preferred"`, `"usable"`, or `null`, and `tags` is an array (including `[]`). No schema version is required. The original source filename is preserved even though storage uses the fingerprint.

Non-skipped clips need an available original and a ready thumbnail; empty attributes do not block processing. Already synced and queued clips are excluded. Review shows count, source-plus-thumbnail size and New rows with blue tags and Update rows with yellow tags. X dims an excluded row but keeps it visible; the control becomes a dash that restores the row when clicked, without changing Skip. Confirming Commit authorizes replacement for included Update rows. Changed source/destination state invalidates review; a later conflict fails the affected entry for a fresh review. Existing source/thumbnail assets with a different extension block processing to avoid ambiguous roles.

The backend captures immutable in-memory clip snapshots and locks submitted clips until completion, cancellation, or failure. One proxy encoder, one Commit worker, and one Export worker run independently and can operate concurrently. Each worker handles one clip at a time; shared fingerprint locks prevent Commit and Export of the same clip at once. Ready submitted clips transfer first while others wait for proxies; submission raises their encoding priority. A background encode below 20% is cancelled to make way for a submitted clip that needs a proxy, then restarts later. Encodes at or above 20%, submitted encodes, and final publication finish first. State is pushed through backend/main/preload notifications without status polling. The centred footer always shows Proxies, Commits, and Exports in fixed positions, with white active counts and dimmed idle counts. Three equal-width bars show each active clip’s actual progress: yellow for Proxy, blue for Commit, and green for Export. Both tabs share these counts and active percentages through one notification subscription; tab switches do not reload queue status. Counts show unfinished clips, including active work, without totals. All three bars stay empty when idle. Thumbnail bars show each clip's progress. The toolbar work control beside Configuration cancels proxy encoding, Commit, and Export work while thumbnails continue. Individual cards carry activity details: discovering clips show a thumbnail shimmer and stay locked until metadata/thumbnail preparation finishes; editable cards remain unlocked during background encoding; queued cards are dimmed and gently pulse; active transfers show a centered spinner over dimmed media. Synced cards have prominent blue backgrounds and changed cards yellow backgrounds, with matching blue/yellow outlines only when selected, and skipped cards nearly black with heavily darkened thumbnails and muted filenames while remaining editable. Other card states have no visible icons or text badges. The top-left media-readiness indicator is dim hollow when unchecked, white hollow while preparing, yellow when the full current asset set is ready to Commit, blue only when complete Library assets match the current metadata/thumbnail, and red when required assets are unavailable or preparation fails. It stays visible on skipped clips, and queue/transfer overlays do not replace readiness. Encoding and transfer use matching 6px yellow/blue/green encoding/Commit/Export spinners over gently darkened thumbnails; transfers take precedence. A 6 px, undimmed progress bar along the thumbnail’s bottom edge is yellow for proxy encoding and blue for Commit or green for Export, without visible numbers; transfer progress takes precedence if both are reported. Hover text and accessible labels explain activity and errors. Yellow card styling describes a pending Library update (including a missing proxy), independently of background encoding. Animation respects reduced-motion preferences.

Successful processing publishes JSON and saves a local receipt for that Library, attributes, and thumbnail content. Synced requires matching attributes/thumbnail plus one source, thumbnail, metadata JSON, and proxy in the latest Library filename check. Reverted metadata edits can restore Synced; selection and Skip do not affect it. Existing core assets without a matching receipt, or with missing required assets, show Needs Syncing. Fully deleted core assets are New even if an optional proxy remains. Receipts persist normally and through an unavailable share, where their status is unverified. The refresh icon beside Configuration updates filename presence after external edits, without opening media or JSON contents. Revert explicitly reads only selected metadata and thumbnail files. Library asset listings are not polled, and no full-file integrity pass is performed.

### Proxy preparation and cache

The app manages its files under `Shot Manager Cache/` in the local app data directory, beside Electron's own `Cache/`. Use **Browse Cache** in Configuration to open it in Finder. It contains `metadata.json`, `thumbnails/`, `fingerprints/`, and `proxies/`. The new Cache starts empty; existing files in the former shared `Cache/`, older `owmo-shot-manager/`, and previously user-chosen Cache locations remain untouched. The Library location remains user-configured and pending until Save; Cancel, closing, or Escape discards a pending choice. Completed files use `proxies/<id>.proxy.mov`; unique `.partial` files stay unpublished until FFmpeg succeeds. Proxy preparation starts automatically for available, non-skipped discovered clips after the Library presence check establishes that a proxy is missing. Completed cache files are reused across renderer/app restarts. One lower-priority encoder starts after thumbnail work is caught up, with bounded decoding/encoding threads; thumbnails have their own worker and do not wait behind a full encode.

The preset is ProRes 422 Proxy in MOV, 10-bit 4:2:2, PCM audio preserving source tracks/channels/sample rate, exact source frame timing and available timecode, with no viewing LUT. Scaling preserves displayed aspect ratio and rotation, fits a maximum 1280-pixel long edge, and never upscales; dimensions are codec-compatible and pixels normalized to square. Standard color declarations are preserved where representable. Camera-specific log/gamut declarations remain in Library JSON; unknown/capture-specific names are not falsely tagged Rec.709 or passed as invalid FFmpeg enums. The intended input is locked frame-rate footage; no VFR conversion workflow is added.

An existing regular `<id>.proxy.mov` in the Library is assumed good. Delete it manually and use Refresh to request regeneration. A submitted clip waits for its proxy without blocking ready clips. After all transfers, metadata publication, and receipt persistence succeed, the matching cache proxy is removed. Failures and Stop retain completed cache proxies. Encoding checks free space before starting and during output and pauses before the drive reaches a 512 MiB reserve; cache has no quota. Inactive clip drafts and receipts, thumbnails, valid fingerprint records, and cache proxies expire after 90 days at graceful shutdown. Saved Identity/Project options and corrupt persisted records remain until explicitly cleared. Unfinished files left by an abrupt application/volume failure are ignored until retention cleanup or manual removal. Clear Cache stops background encoding before removing the selected app-owned files; keeping proxies leaves those files available for later reuse.

Rsync preserves source modification times and uses its size/mtime quick check to avoid recopying unchanged videos when metadata changes. Thumbnails are copied from a private temporary snapshot. Library directory listings are shared across each review/submission; execution checks the known target paths. Saving the selected Library records its mounted volume in configuration; older settings require choosing the Library again before processing clips. The destination must already exist, differ from the source folder itself, match that configured volume, and retain its reviewed folder/mount identity. Missing `/Volumes` mounts, symlink assets, and unreviewed target changes are rejected; the app never creates a missing Library root. Option removal and cache clearing are blocked while clips are queued. Folder discovery can continue, and Eject cancels selected clip jobs before removing their records. Changing the configured Library is also blocked while processing is active.

The toolbar work control beside Configuration shows **Refresh** when idle/paused and spins during work; hovering or keyboard-focusing it reveals a red **Stop** square. Refresh checks Library and cache presence, then resumes missing thumbnail/proxy preparation; it never resubmits cancelled Library transfers. It is disabled while checking. Stop confirms before cancelling transfers and proxy encoding, clearing their queues, and suspending automatic proxy generation. Thumbnail generation continues, including for clips added after Stop. Thumbnail-only activity does not offer Stop; shutdown and Cache clearing still settle thumbnails safely. A stop during a presence check prevents its completion from restarting workers. Toolbar Stop cancels queued and active proxies, Commits, and Exports; inspector Stop cancels individual Commits. Completed Library clips remain synced; cancelled submissions unlock and preserve receipts/pending changes. Completed cache proxies remain reusable. Clicking Commit refreshes Library/cache presence and resumes required preparation before review; transfers start only after confirmation. A late Commit review cannot restart work after Stop. Ordinary metadata editing remains available for prepared, unsubmitted clips. Failures show clip/error details, unlock/remove failed submissions, and allow remaining ready clips to continue. A later explicit Commit/Refresh can retry proxies. Library orphan cleanup and durable recovery remain deferred.

The queue survives renderer reloads, but is not persisted across application crashes/restarts. Graceful shutdown stops transfers before closing the backend. Only the usual drafts and successful processing receipts persist; there is no durable queue journal or automatic resume. A crash between Library publication and receipt persistence can leave a processed Library shot without a local checkmark; it will appear as Update in a subsequent review.

The Library tab uses the same grid, original-video preview, attributes, and device filters, with separate filter/selection memory. Cards are neutral by default and yellow for local metadata differences; Skip and Eject are Import-only; Thumb is available in both tabs. Successful Import Commits remove their workspace cards and add/update the catalogue immediately. Re-adding a matching original can still show blue in Import. Import Commit review also lists Synced cards in its selected or all-clips scope for workspace removal. Nothing leaves until confirmation; X/dash excludes/restores any row, and excluded Synced rows stay. Selected-only Commits leave unselected synced cards alone. A review containing only Synced rows removes the included cards without transfers. Files, drafts, receipts, and Library assets are kept.

Library opens its cached view, then refreshes JSON with four concurrent readers. `catalogue.json` is separate from shared pending drafts in `metadata.json`; refresh preserves edits, clean drafts adopt remote changes, and offline/invalid records retain cached information. Thumbnails are loaded on demand into `library-thumbnails/`. Library Thumb changes stay in the shared local thumbnail Cache and turn the clip yellow. Commit reviews and queues changed thumbnails plus metadata through the existing worker, transferring the thumbnail with rsync before publishing JSON. Originals, proxies, technical metadata, and additional JSON fields stay intact. Revert restores selected current metadata and thumbnails; differences need no conflict prompt. Clear Cache can keep/clear the catalogue independently of metadata. Export opens the native destination picker first, then reviews the explicit Library selection and chosen destination with X/dash exclusion/restoration. Included clips must have no pending metadata or thumbnail changes. Export prepares Resolve media using rsync: sources go directly in the selected folder as `<original-stem>__<fingerprint-prefix>.<ext>`, matching proxies in `Proxy/`, and dated batch CSVs in `Metadata/`; per-clip app JSON is not exported. Unsafe filename characters are replaced and long stems shortened; the fingerprint prefix starts at eight characters, extends on collisions, and reuses established names by checking existing sources with the sampled fingerprint. Existing targets are reviewed as Update and rechecked before writing. Each accepted batch creates a dated CSV containing only successfully exported clips; later exports keep earlier CSVs. There is no Media wrapper, transcoding, or embedded metadata rewrite. Editor naming/CSV formatting is separate from the guarded transfer worker. Export has its own serial transfer worker and green progress bar, shares toolbar Stop, and locks affected clips. All three footer sections remain visible when idle. Library assets and receipts stay unchanged. The Library inspector shows Thumbnail, Export, and Delete as icon-only actions with hover labels. Delete reviews the selected clip list with red Delete tags and X/dash exclusion/restoration, removes all flat `<id>.*` Library files (including derived assets), and clears their local catalogue entries/drafts/receipts. Queued/active clips cannot be deleted; stale files, symlinks, and changed mounts are rejected. Deletion uses ordinary filesystem removal; any recycle behavior belongs to the NAS. Source-card footage, Exports, and saved Identity/Project options are kept. Failures identify affected clips; incomplete clips remain available to review and retry. Resolve importing/plugins and expanded search remain deferred. Local scale checks do not establish SMB performance; real NAS access requires explicit authorization.

For a manual Resolve test, import the exported source footage, then link the `Proxy/` files if needed. Define Identity, Project, Group, Camera, and Quality as Text Input fields under **Manage Custom Metadata > User** for reuse across projects. Use **File > Import Metadata To > Media Pool** and select that batch’s `Metadata/` CSV. Match filenames; disable start/end timecode matching because the CSV does not include timecodes. With those fields defined, disable “Import additional metadata fields as custom metadata” to avoid creating Project-scoped duplicates. “Update all metadata fields available in source file” applies blank exported values without clearing unrelated fields. CSV uses minimal quoting for Resolve filename matching, escaping commas, quotes, and line breaks when needed. No importer is installed.

CSV maps Scene to Description, Group to Scene, Camera to Camera #, Notes to Comments, and Preferred/Usable to Good Take (true/false). Clip Name combines populated descriptive fields with the original stem. Identity, Project, Tags, and Quality contribute searchable Keywords; custom columns preserve the original values. All attributes remain optional.

## Development

The app uses Electron and React in `desktop/` and `client/`, a local Fastify backend in `server/`, and shared types in `shared/`. The renderer accesses files through restricted preload/backend interfaces. The backend runs in a separate Electron utility process.

Clip attribute keys are `identity`, `project`, `scene`, `group`, `camera`, `rating`, `notes`, and `tags`: Identity/Project and Quality (stored as `rating` for compatibility) are nullable single values, Scene/Group/Camera/Notes are text, and Tags is a list. Older drafts and Library JSON load missing grouping fields as blank, preserving existing synced receipts when they are empty. The independent `skipped` boolean persists with the draft, defaults to false, and is preserved by Clear. Older `projects`/`context` records migrate atomically to `project`/`tags`, with prior multiple-project assignments retained in recovery metadata. Scene, Group, Camera, and Notes have separate debounce keys and share the main-process save/retry/quit handling.

IPC carries structured error data so messages, codes, HTTP status, and unknown mutation outcomes survive the preload boundary. Backend reads have a 15-second deadline; mutations wait for a response. A lost mutation response is reported as an unknown outcome, rather than claiming cancellation. Only the existing idempotent clip-attribute commands are retained for explicit ordered retry; processing submissions are not automatically retried. If a submission response is lost, the UI checks current queue status instead of assuming nothing was queued.

Workspace ownership lives in `server/scanner.ts`; `server/workspace.ts` accepts temporary ID/path discovery requests and monitors referenced directories. There is no Source registry or source-level rescan/remove/relink API. Rediscovery is additive and never removes or locks existing cards. Commit uses eligible selected clips, or all eligible clips when nothing is selected; an ineligible selection never falls back to everything. Accepted submissions append immutable snapshots, retain progress history, and reject stale/conflicting additions independently. Per-clip Stop retains/unlocks cards; Eject removes unqueued clips; toolbar Stop cancels proxies, Commits, and Exports while thumbnails continue. Successful publication retains its receipt even if cancellation races with completion.

Workspace snapshots return cached state without touching media. Backend monitoring checks each unique clip-containing directory every five seconds and revalidates affected files when a missing directory returns. Routine checks do not enumerate contents, inspect every video, detect mounted volumes, or poll the folder originally selected. Unavailable directory members are flagged together, with one consolidated path/count dialog per outage offering Eject affected clips. Cached information remains editable. Recovery respects a manual Stop; unavailable queued media follows the existing failure/removal policy, with Commit needed to resubmit. Monitoring references disappear with the final workspace member. Individual file access validates the stored absolute path and file identity. Change events carry revision notices instead of collections. The renderer coalesces notices over 250 ms and permits one snapshot request at a time; vocabulary has its own revision so preview, Notes, and Skip changes do not reload suggestions.

Clear Cache restarts the backend and reloads the workspace so snapshot revision counters reset together. The navigation guard permits reloading the current app URL while blocking navigation to other URLs.

Clip-attribute edits still save atomically before acknowledgment. Scan-only bookkeeping is batched in groups of up to 64 records and flushed on scan completion and graceful shutdown. An abrupt process exit can lose the latest bookkeeping batch, while acknowledged attribute edits remain saved.
