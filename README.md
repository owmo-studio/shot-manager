# owmo-shot-manager

MacOS electron desktop application for reviewing source footage (SD Cards, folders, etc.), adding shot metadata, and ingesting them into my NAS source library.

## Development

Requires Node.js 22.12+ (a supported LTS release is recommended) and npm.

```sh
npm install
python3 scripts/setup-luts.py
npm run dev
```

Opens an Electron window with a React/Tailwind interface and a separate local Fastify backend. The footer checks the backend connection. Use **+** to choose a mounted card or ordinary video folder. Recognized Sony structures show a camera icon and sample embedded original-file metadata for their source name. Every video's metadata is inspected independently of folder names; external XML sidecars are not required or read.

The top-right **Configuration** gear opens a floating settings dialog with Library and Local Data buttons followed by their current path or usage. The Library path beside the gear is plain, non-clickable text. **Set Library location** opens a native folder picker and saves the selected full path atomically in `configuration.json` under Electron's user-data directory. The location persists across launches and appears beside the gear (full path on hover); an unset location reads **library needs to be set** in red. Cancelling the picker preserves the previous value. This setting does not create, scan, or write to the Library, and does not authorize real NAS ingestion.

**Local Data** displays thumbnail size/count and the number of saved options. **Clear Local Data** deletes cached thumbnails and the local Identity, Project, and Context option lists, while preserving all fingerprint-keyed clip records, Notes, configuration, and fingerprint records. Available sources are automatically rescanned; those scans rebuild the lists from retained clip information, dropping unused options. Unavailable sources keep their saved information and contribute options when scanned again. Previews regenerate as needed.

Configuration also lists saved **Identity**, **Project**, and **Tags** options in scrollable boxes. Use × to stage deletions, then **Save** to update the option lists and rescan available sources. Cancel, closing the dialog, or Escape discards staged deletions. Saved clip metadata is unchanged; a rescan adds back values still used by scanned clips. Correct accidental values on clips before removing their unused options here. Library selection and Clear Local Data remain immediate actions.

The **Metadata** tab edits Identity (one plain value), Project (one plain value), Context (multiple grey tags), and Notes directly on the selected clips. Identity and Project use searchable select-or-type dropdowns: choose an existing option or type a new name, including spaces/capitalization, and press Enter or Tab. Names are limited to 128 characters and duplicate options are matched case-insensitively. Their × clears the value. Context remains lowercase, with Space/Enter committing a tag and Tab completing a suggestion. Clicking Context opens the complete scrollable list; typing filters it. Context tags allow slash-separated hierarchy (e.g. `music/rock`), up to 64 characters with no empty or leading/trailing slash segments. All color assignments have been removed.

With multiple clips selected, plain Identity/Project values and grey Context tags show coverage counts for partial matches; shared Context chips are filled and partial ones outlined. Adding Context tags preserves existing values. Choosing Identity or Project replaces that field on all selected clips. Removing a Context chip removes only that tag. Mixed Notes show a placeholder; typing replaces selected Notes. Identity, Project and Context changes save immediately without Apply. Notes save after a 500 ms typing pause, with pending text flushed on field blur, selection/tab changes, before rescan/removal/clearing, and when quitting. Failed saves offer Retry. Offline clips remain editable; rescans lock changes until reconciliation finishes.

The bottom-right **Clear** button in the Metadata tab asks for confirmation before resetting Identity, Project, Context, and Notes for the selected clips. Its dialog says “Metadata will be cleared for N selected clips.” without a files/thumbnails note. Cancel/Escape preserves everything. Clear keeps clips in the workspace, preserves their technical metadata, video files, thumbnails, fingerprint records and option lists, and respects edit locks. It is separate from clearing Local Data.

Version-3 `organization.json` stores fingerprint-keyed clip drafts and independent option lists. Older color assignments are removed during migration; clip data is retained. Identical copies share a draft. Each successful scan restores the draft, renews its 90-day retention, and collects its Identity/Project/Context values into the local lists. Edits renew retention too. Inspector/grid display and availability polling do not count as scans. Expired drafts are cleaned up at session end; option lists do not expire automatically but can be explicitly reset with Local Data. Source removal does not delete retained drafts. Tag management, Library searching, and ingestion remain deferred.

Older multi-project drafts keep the first active project; original assignments remain in the retained draft as `previousProjects` until the draft expires or the clip is explicitly cleared. The internal `projects` array remains for compatibility and holds zero or one value.

`npm run check:organization` validates atomic/bulk saves, lowercase/hierarchy validation, persistence, scan renewal/expiry, permanent vocabularies, offline editing, corruption/lock recovery, and restoration after a backend restart with dummy sources. `npm run check:selection` includes Organize field interactions, Context autocomplete, neutral shared/partial tags, plain dropdown values, Clip Clear confirmation, Notes, and renderer reloads.

The small **LUT** button beside the thumbnail action is on by default for each inspected clip. Declared Sony S-Log3/S-Gamut3.Cine and Apple Log/BT.2020 footage use their manufacturer viewing transforms for Rec.709 review. Turn it off to see the original image without reloading or moving the playhead. Rec.709 passes through. Unknown profiles, other gamuts/log curves, HLG, and PQ receive no guessed transform; the preview explains when no matching transform is available. Original file properties and bytes remain unchanged.

Viewing uses a WebGL2 canvas with compact playback/seek/audio/fullscreen controls; no proxy or temporary video is generated. GPU failure falls back to native original-video playback with an explicit message. Missing/invalid LUTs show the original with a message and disable transformed frame capture. The source decoder's RGB precision and display color management make this a review aid, not a calibrated grading pipeline. Generated and custom thumbnails use the enabled transform even when the preview LUT toggle is off; cache keys include the LUT fingerprint and pipeline version, so old untransformed entries are not reused. Setup uses Sony's official download and an Apple table from installed iMovie; see [local LUT setup/provenance](resources/luts/README.md). Tables remain local and gitignored.

Adding a source starts a read-only recursive scan for common video extensions; hidden entries and symlinks are skipped. Each original video is one shot. Camera thumbnails, sidecars, and proxies are not assembled into associated-media bundles. Legacy Sony `SUB` folders in recognized layouts and files explicitly declaring an embedded Sony proxy codec are excluded. Generic videos are not excluded merely for a `SUB` directory or `S03` filename. Sources scan sequentially and results are cached in memory. Refresh and **×** controls appear on hover or keyboard focus. A rescan stages new results, re-extracts metadata, then commits additions, removals, and updates together; changed files invalidate cached preview state. Failed/incomplete rescans keep the old list. Status polling does not repeatedly probe every video.

Source removal is disabled while its scan is queued or running, and the backend rejects removal during those states. Removal becomes available after completion, failure, or interruption.

Scan transitions are pushed from the backend through Electron to the interface immediately, with progress updates coalesced to about 100ms. Waiting sources show **Queued...**; only the active source shows **Scanning...**, a spinner, and blue styling. Revision numbers prevent delayed request responses from overwriting newer scan events. Five-second polling remains for source availability, backend health, and recovery of current state.

For a newly added source, each clip appears after its metadata inspection finishes. Thumbnail cache lookup and generation happen on demand after discovery. Processed clips are immediately available for inspection and thumbnail changes while remaining clips continue scanning. Grid additions and the source counter share batched progress updates. New cards enter with a brief 180 ms fade and slight upward motion, disabled when reduced motion is preferred.

During a queued or active rescan, existing clips remain visible, greyed out, and non-editable until reconciliation completes. Additions and removals are committed together at completion; other sources remain unaffected. Unavailable sources retain their red error state.

Refresh is disabled for unavailable sources or while a scan is queued or running. The backend revalidates the source before starting a refresh and rejects concurrent refreshes. Failed or interrupted sources can be refreshed after reconnecting. A detected replacement source identity is treated as a new source rather than merging old-card clips.

For an unavailable source, the refresh control becomes **Re-link** (chain icon). Choose its new folder with the native picker to automatically queue a rescan, preserving its position in the source list. Cancelling or choosing an unreadable/already-added folder leaves the old entry intact. A moved original directory with the same inspected identity retains its source/clip IDs and skip choices; existing clips remain greyed out until reconciliation completes. A different directory/card gets a fresh identity and scan, without inheriting old clip state. Re-linking never modifies source files.

Clicking **×** opens a **Cancel / Proceed** confirmation. Proceed removes the source and its clips and metadata from the current workspace; files on disk are never deleted. Cancel or Escape leaves the workspace unchanged.

Source-action errors, including rejected individual file drops, appear in a dismissible popup rather than remaining in the Sources list. Use **Dismiss** or Escape to close it. Repeated background refresh failures notify once until monitoring recovers.

The combined shot grid groups by recording date and stays newest first. The grid has no summary header, filter-description line, or reorder button. Sources and Devices use larger headings; Sources shows the total discovered clip count once nonzero, across all sources regardless of active filters or skip choices. Source rows toggle multi-source filters; no active filters means all sources. Capture-specific embedded dates retain their offsets; generic container creation and filesystem modification times are marked uncertain rather than silently treated as recording time. Missing timezones are not replaced with the computer's timezone. FFprobe has an eight-second timeout; unreadable/unsupported candidates retain unknown fields and warnings where possible. This is discovery, not integrity verification.

Sony FX30 and ZV-E10 II metadata works from card roots, copied camera folders, or standalone originals in arbitrary folders. A bounded MP4/MOV reader extracts embedded XML and Apple Log sample-entry declarations without reading the video payload. Source structure is used only for source presentation and legacy-proxy exclusion; no sibling folder outside the selected root is accessed.

Every default preview is a cached first frame extracted from the original video on demand by a sequential FFmpeg queue. Camera proxies and thumbnails are never used. Images fit within 480×270 pixels. Each extraction has a 12-second timeout; failures retain the placeholder without affecting scan/edit eligibility. **Preparing thumbnail…** indicates queued generation; completion is pushed to the interface.

Generated and manually captured previews are cached under Electron's user-data directory in `cache/thumbnails/`, outside the source folder and repository, with a 90-day expiry. Keys use a versioned sampled SHA-256 fingerprint: exact file size, common embedded recording date/duration/codec/dimensions/frame rate/frame count (when available), and five non-overlapping 256 KiB windows spanning the beginning, 25%, middle, 75%, and end. Files up to 1.25 MiB are read once in full; larger files require only 1.25 MiB of fingerprint reads. The first window includes the header. Metadata field order is fixed; paths, filenames, filesystem dates, and source/camera-specific identifiers are excluded. Identical videos with the same embedded metadata reuse generated/custom previews across locations and sessions. This is a probabilistic cache association, not a full-file checksum or a globally unique recording ID. Changes outside sampled regions can go undetected.

Every scanned video receives a `fingerprint` record with algorithm, scheme, digest, file size, sample size, and bytes sampled. Versioned per-file JSON records live in Electron user data under `fingerprints/`, separate from the disposable thumbnail cache; clearing previews preserves them. Unchanged filesystem-version hints and normalized metadata permit reusing saved records after restart, while copies/renames may require bounded resampling. File stats are hints only and never part of the fingerprint digest. Reads are cancellable and reject concurrent file changes. Fingerprint failures leave clips visible with a retry warning. No database or source-file writes are introduced. Old path-based cache entries migrate when their old location is known; older full-file-hash entries without a recoverable association may need a one-time preview rebuild/custom thumbnail reset. Cached previews are application data, separate from source videos; there is no associated-media list or indicator. Cache files are written atomically; source media is never modified and no temporary video copy is created. Concurrent requests for a clip share one generation task. Removed or refreshed source jobs cancel their old thumbnail tasks. FFmpeg receives local input paths and writes image bytes to its output stream, never to the card. If the cache is unwritable, a successfully generated image can still be displayed in memory. Per-source clip counts update as scanning progresses. Organizational metadata editing is implemented; ingestion remains deferred.

Click anywhere on a clip card to select it for inspection and metadata editing. A plain click selects only that clip; clicking the sole selected clip again deselects it; Cmd-click (Mac) or Ctrl-click toggles additional clips, and Shift-click selects a range in displayed order, across day groups. Cmd/Ctrl+Shift adds a range to the current selection. Escape clears these editing targets without changing skip choices. Clicking empty space in the shot area clears the editing selection while preserving skips; card and control clicks are excluded. All deselection methods also release card/inspector focus to prevent a lingering focus outline. Tab and Shift+Tab are deliberately blocked except that unmodified Tab inside a tag input commits the highlighted suggestion (or the typed tag). The right panel remains visible with the same blank, muted layout when no clip is selected. Playback uses the original only, with seeking and an unsupported-codec message rather than automatic transcoding. Rescans/unavailable sources pause preview. Source/proxy generation workflows are deferred; there is no Proxy toggle or associated-media badge/list.

With a clip selected, **Left / Right** select the previous/next selectable clip in the current filtered display order, including across date groups. **Up / Down** move to the closest column in the visual row above/below, measuring the rendered cards on each keypress so window/inspector resizing and partial rows work naturally. Navigation stops at the edges, skips rescanning/locked clips while including unavailable clips, preserves skip choices, and scrolls/focuses the new card. Keyboard scrolling leaves 20px of breathing room around the full card and includes the date heading when entering the first row of a day (when both fit). From a multi-selection, arrows continue from the most recently active clip and select one clip. Inputs, video controls, inspector tabs/resizing, and open dialogs keep their own arrow-key behavior; modified arrow shortcuts are left alone.

Skipping is controlled **only from the right panel**; shot cards have no X button or skip checkbox. All discovered clips are included by default. Skipping excludes a clip from future ingestion without changing its editing selection. Only the thumbnail dims (45% opacity); filenames, metadata, and outlines remain at full brightness. Skipped cards retain their red tint and red editing-selection outline, and remain inspectable/editable. The inspector's **X + Skip** control matches the other header buttons' height, padding, and font, with a stronger red fill, border, and subtle ring when active. It stays beside **Set thumbnail** and applies to the current editing targets; a mixed state means only some are skipped. If any selected clip is skipped, clicking the side-panel checkbox clears skips for all selected clips first; a subsequent click skips all. Multiple editing targets retain the compact filename list and editable Organize fields. The footer counts non-skipped clips and skipped clips across all sources, including hidden clips. **Review & Ingest** remains disabled; no processing starts.

Changing filters clears editing targets that become hidden, while retaining explicit skip choices. Removing a source or clip prunes its selections. Unavailable clips remain selectable and can change skip choices; rescanning clips retain choices but cannot change them until reconciliation completes. Selections remain **session-only** and reset on renderer/backend restart. Organizational drafts persist locally by fingerprint; durable skip/selection drafts, review, immutable queue snapshots, and processing remain future work. `npm run check:selection` builds and runs synthetic Electron interaction checks without touching cards or NAS media.

The inspector has **Metadata** (editable organizational tags and notes) and **File info** tabs. File Info leads with **Device, Codec, Color space, Resolution, and Frame rate**, including bit depth/chroma, orientation/display dimensions, and a single fps value. Duration follows Frame rate as HH:MM:SS:FF; filename/path, size, and date continue in the same list. Timing details, color range, and metadata provenance remain in diagnostics rather than summary sublabels. Unknowns remain unknown; color evidence and conflicts are retained. Sony embedded XML identifies capture settings; native iPhone/Blackmagic tags identify device/software; Apple `logs` declarations identify Apple Log even when FFprobe omits the transfer function. Large or unsupported timing tables leave timing mode unknown. Below the combined information list is a collapsible **Embedded metadata** XML/JSON/text blob with copy support. Inspected selection is separate from future ingestion selection. Original video bytes stream through the restricted `shot-media://` protocol and authenticated range-capable backend routes.

The inspector defaults to a minimum width of **560px**. Drag its left edge to enlarge it; the width is retained while switching clips or reopening the panel within the session. The focused divider supports arrow keys (Shift for larger steps), Home/End, and double-click to reset. Resizing leaves room for the source list and clip grid; the application window has a minimum width of 1100px.

The image button at the top of the inspector captures the current frame with its viewing transform as a custom JPEG (up to 480×270), replacing any previous capture. It is an action, without toggle/unset behavior. Captured frames take priority over generated first frames and survive restarts while cached, with the same 90-day expiry. Cache keys use the versioned sampled video fingerprint, not its location or session shot ID; identical copies intentionally share the custom capture. Failed saves preserve the previous preview and show an error. Source files are unchanged.

At session end, cached thumbnails and abandoned cache temporary files aged **90 days or more** are removed. Scanning a video renews its matching cached previews; generating/capturing a preview also renews that image. Cleanup waits until shutdown so returning sources can renew their cached data before deletion. It touches only recognized cache filenames, skips directories and symlinks, and never touches source media. Missing cache folders are harmless; cleanup failures are logged. The expiry default is centralized in `server/thumbnails.ts`; exposing it in the configuration panel is deferred.

Sources last only for the current backend session. Previous `sources.json` files are no longer read or written. Selected paths are rechecked about every five seconds: missing or inaccessible roots remain in the list as unavailable, with one combined popup listing newly unavailable sources by name and full path. Additional failures join the open dialog; recovered/removed sources leave the list. Dismiss or Escape acknowledges the entire batch, with each source notifying only once per outage. Restoring the path clears the unavailable state; a later outage can notify again. Renamed or moved folders can be removed and added at their new location. Changed root identity or sampled metadata creates a fresh source ID. This is live detection, not a guarantee of physical card identity; ingestion will need stronger source validation. Camera models reflect the metadata sample, not an assertion that every shot uses the same camera. No shot-specific configuration is reused between cards.

Use **×** beside a source to remove it from the list without deleting or changing any files. Disconnecting or renaming a source stops any active scan but retains discovered shots and already-loaded thumbnails in the grid. Those shots remain selectable with red styling, cached File Info, and a red preview placeholder labelled **source unavailable**. Skip choices and Organize drafts may be edited offline; playback, thumbnail capture, and ingestion still require source availability. Scans are not automatically repeated on reconnection. Removing a source explicitly clears its shots; replacement source identities also discard old results. Sources and shots remain session-only. The central **+** opens the same picker as **+ Add Source**. Folders or mounted cards can also be dragged from Finder onto the main workspace, including after sources have been added. Individual file drops are rejected. The native picker belongs to the desktop shell; source registration, discovery, and metadata inspection belong to the backend.

`npm run build` checks TypeScript and builds into `out/`. `npm start` opens that build; it does not create an installable application.

## Structure

- `desktop/`: Electron lifecycle and restricted preload bridge.
- `client/`: React interface, styled with Tailwind via Vite.
- `server/`: Fastify service in a supervised Electron utility process.
- `server/discovery.ts`: Recursive original-video discovery and normalized file inspection.
- `server/embedded.ts`: Bounded MP4/MOV embedded XML, log declarations, and frame timing reads.
- `server/videoMetadata.ts`: First-class file metadata normalization, evidence, and unknown/conflict handling.
- `server/scanner.ts`: Background scan lifecycle, cancellation, cached results, and controlled thumbnail reads.
- `server/thumbnails.ts`: Sequential frame extraction and local thumbnail cache.
- `server/media.ts`: Read-only video streaming with byte-range support.
- `shared/`: Frontend/backend types.

The backend listens on a random loopback port with a per-launch token. The frontend requests status through the preload bridge; it has no direct Node.js or filesystem access. Closing the last window or using Cmd+Q quits the app and stops the backend. An explicit native Quit menu and main-process shortcut handle Command+Q independently of renderer focus; accepted metadata saves drain before shutdown, with a bounded forced-exit fallback. `npm run check:quit` tests the real Electron/backend lifecycle with a hidden window, isolated temporary user data, and pending writes. Frontend edits reload automatically; restart development after changing backend code.

Ingestion and durable recovery features are future work. Develop against isolated dummy folders; reading an explicitly selected source is read-only. Real NAS access requires explicit configuration and authorization.
