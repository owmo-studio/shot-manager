# OWMO Shot Manager

OWMO Shot Manager is a local macOS desktop app for browsing original video footage from cards and folders, inspecting clips, and assigning per-shot attributes. Commit places clips, proxies, thumbnails, and metadata in the Library. The current Import workflow prepares ProRes proxies in app-managed cache storage, copies original footage, thumbnails, and missing proxies into the canonical Library, and publishes metadata through a reviewed transfer queue. Development validation uses isolated dummy sources and local destinations; real NAS validation remains pending.

## Requirements

- macOS, Node.js 22.12+, and npm
- macOS bundled `/usr/bin/rsync` (or compatible openrsync)
- FFmpeg and FFprobe available on `PATH`, with the `prores_ks` encoder and the scale filter’s `reset_sar` option

## Run locally

```sh
npm install
npm run dev
```

Viewing LUTs are included in the repository. See [LUT provenance](resources/luts/README.md). `npm run build` checks TypeScript and creates `out/` with the LUTs; `npm start` opens that build. This repository does not currently produce an installable app.

## Current functionality

- Add multiple card or folder sources, browse original videos by recording date, filter by device, inspect technical metadata, and play or seek the original video. Clips appear after fingerprinting and attribute loading; their identity follows the fingerprint across moves and rescans. The backend workspace holds one record per fingerprint and one active absolute file path per clip. Repeated or overlapping additions retain an existing valid path and its state; a freshly fingerprinted matching copy replaces an unavailable path. A queued Commit keeps its captured path until completion or cancellation. Adding a folder again performs additive discovery without resetting existing cards. The left panel contains All (with total clip count) and per-clip device filters; All clears active filters; folder scanning appears as temporary progress above the grid. There is no Source list, source filtering, source rescan/remove control, or Devices heading. The backend queues thumbnail generation for every identified clip during scanning, independently of card visibility or renderer reloads, using one worker and reusing cached/custom previews. Scanning continues while thumbnails are pending; preview failures do not prevent clips appearing. The grid loads cached images as cards approach the viewport. Camera proxies, thumbnails, and external XML are not used.
- Add folders through + or drag and drop, or drop individual supported video files, including while other clips are committing. File drops inspect only those files; non-video extensions are rejected. Adding is disabled for critical red application issues such as Library Not Set; the empty workspace reflects that issue. Yellow warnings do not block discovery.
- Edit Identity, Project, Scene, Notes, and Tags per clip. All assigned attributes are optional, including when processing clips. Attributes and Skip choices persist locally; workspace membership and editing selections are session-only. Successful processing receipts persist with local drafts. Skipping a clip is separate from selecting it for inspection.
- Eject a single clip with its card icon, or use Eject in the inspector for a single/multiple selection. Eject asks for confirmation, then removes workspace membership and cancels only those clips’ unfinished jobs. Queued/active Commits show Stop (outlined square) instead of Eject. Stop confirms the affected clip list, then cancels only the selected Commit snapshots, keeps their clips selected in the workspace, and unlocks them after the transfer settles. Background proxy encoding continues independently. A subsequent click offers Eject (triangle/bar). In mixed selections, Stop affects only queued/active clips and preserves all membership. Selected queued/active cards have a clear light outline. Original footage, Library assets, cached metadata/Skip, receipts, and completed proxies are preserved. Ejected clips are excluded from late scan results; explicitly adding their folder again can restore them.
- Use the LUT toggle over the video's top-left corner to review supported Sony S-Log3 and Apple Log footage. Viewing transforms and cached previews do not change source files. Thumb, Skip (circle-minus), and Eject sit in the inspector header; each card also offers Eject at the thumbnail’s top-right, opposite the Proxy indicator.
- Set a Library location in Configuration. The app checks the mounted destination and lists its asset filenames on startup, after saving the location, and before processing review. This presence check does not open media or JSON contents or write to the Library. **Commit** confirms an explicit clip list before queueing transfers. See the processing behavior below.

Configuration shows a Cache Summary with clip-entry counts and file sizes for metadata, thumbnails, fingerprints, and proxies. **Clear Cache** confirms which app-owned Cache files to delete. Check **Keep metadata**, **Keep thumbnails**, **Keep fingerprints**, or **Keep proxies** to retain those categories; unchecked categories are cleared. Metadata includes local clip attributes, Identity/Project lists, and commit receipts. The workspace reloads after clearing, restoring exact surviving file paths and unfinished discovery with Eject exclusions. Completed folder roots are not rescanned, so ejected sibling clips stay out. This is an in-memory handoff during Clear Cache, not a persisted queue or crash-recovery journal. Source videos, Library assets, and the saved Library location remain untouched. **Browse Cache** opens the app-managed `Shot Manager Cache` folder in Finder. A small X beside the Library location stages clearing that setting for Save.

The inspector orders fields as **Identity → Project → Scene → Notes → Tags**. Clear and Revert sit at the bottom-left of the attributes panel, with the Saving status aligned right on the same row for single and multiple selections. Clear is disabled when all five descriptive attributes are empty across the selected clips; Skip alone does not enable it. Revert is enabled for selected clips with pending updates and requires confirmation before replacing their local attributes and thumbnails with the current Library values. In a mixed selection it applies only to clips with pending updates. It reads only the selected metadata and thumbnail files on demand after validating the configured Library volume; normal presence scans still read filenames only. It preserves Skip and processing receipts. Missing Library assets may still need processing. Missing, invalid, or symlink Library metadata/thumbnails reject the whole selection; failed draft saves roll back staged thumbnails; successful restores refresh the inspector immediately and retain restored Identity/Project options. Scene is an optional short sentence, saved with each clip like Notes, with no suggestion list. It allows up to 80 characters: Unicode letters and numbers, spaces, apostrophes, commas, periods, and hyphens. Curly apostrophes and long dashes normalize to plain punctuation; extra spaces are collapsed. Notes has a larger six-line editor, and the default window keeps all attribute fields visible. Widening the right panel enlarges the video preview proportionally, with the original image aspect ratio preserved. The character policy does not affect fingerprint-based Library filenames.

Identity and Project options persist; Tag suggestions reflect tags used by currently loaded clips, while clip tags remain saved in drafts. Removing Identity or Project options in Configuration clears only the matching field across local clip records. **Save** shows an affected-clip count and table distinguishing active and saved clips before confirmation; unused entries are deleted directly. No rescan is triggered. Other attributes stay intact. Removal waits for active scans to finish; changed attributes require a fresh review. Older saved records without a filename show a clip identifier until scanned again.

Unreadable or invalid saved drafts, configuration, and fingerprint records are preserved and reported. A clip whose fingerprint or draft cannot be loaded is skipped during discovery; discovery issues appear in the scan summary. Clear Cache remains an explicitly confirmed operation.

Failed clip edits remain in the main process for the current app session, including across inspector changes and renderer reloads. An app-level banner offers retry; later edits wait behind failed edits so retry preserves their order. Source changes, option removals, and reset wait for successful saves. The window close button and Command+Q use the same exit path: finish accepted edits, stop the backend, then close the window. The window displays shutdown progress while background work stops; failed saves offer Keep Working, Retry Saves, or an explicit Quit Without Saving. Retained unsaved edits are in memory, not a crash-recovery journal.

Clip fingerprints use `sampled-sha256-v2`: file size, the fixed sampling scheme and byte ranges, and bytes read from the original file. Large files use five 256 KiB samples spread from the start to the end; files up to 1.25 MiB are read in full. Extracted metadata, paths, and filesystem dates do not contribute to clip identity. Filesystem details only invalidate cached reads and detect changes during inspection. A sampled fingerprint associates local drafts and previews; it does not prove duplicate content or transfer integrity. Processing accepts successful rsync completion without a separate full-file SHA-256 pass. Rsync uses size and modification time to skip unchanged destination files; this is not independent verification of stored destination bytes. This development change does not migrate earlier fingerprint records or their associated drafts/previews.

The footer’s single application indicator shows **Ready** in green after successful checks; red indicates missing/invalid or unavailable Library storage, or communication failure, and yellow indicates unavailable media or proxy preparation. Only the highest-priority message appears, with the newest report winning among equal priorities; hover for details. Startup checks retry quickly until the backend connects; the normal five-second health cycle then checks the configured Library folder/mount without listing Library assets or opening media. A backend startup failure shows Backend Unavailable rather than leaving Starting on screen. The app-managed Cache is not a monitored location; proxy preparation reports its own errors. Slow checks remain yellow rather than reporting a false Ready state. Saving configuration requests an immediate status refresh. Existing detailed dialogs remain available.

## Library and processing

The Library is flat. Asset filenames are `<full-lowercase-sampled-fingerprint>.<role>.<ext>`:

```text
<id>.source.mp4
<id>.thumb.jpg
<id>.metadata.json
<id>.proxy.mov       # ProRes 422 Proxy
```

Sources retain their original format extension, normalized to lowercase. Processing copies the original video, current generated or custom thumbnail, and a missing proxy with rsync, then atomically publishes metadata JSON last. Existing Library proxies are assumed good and retained without content inspection or replacement. Other tools can discover additional assets using the ID and role; other additional assets remain untouched. Temporary and partial filenames are not published assets. Bucket directories, a shared database, and asset-inventory manifests are not used.

The metadata JSON contains `id`, `fingerprint` (including its sampling scheme), `originalFilename`, `bytes`, `recordedAt`, `dateSource`, `dateEvidence`, `dateConfidence`, `durationSeconds`, `metadata` (the existing technical metadata structure), `warnings`, and `ingestion: { completedAt, transfer: "rsync" }` (the existing stored field for processing completion). It always includes all five assigned attributes: `identity` and `project` are strings or `null`, `scene` and `notes` are strings (including `""`), and `tags` is an array (including `[]`). No schema version is required. The original source filename is preserved even though storage uses the fingerprint.

Non-skipped clips need an available original and a ready thumbnail; empty attributes do not block processing. Already synced and queued clips are excluded. Review shows count, source-plus-thumbnail size, exact file mappings, and New/Update rows with neutral blue tags. A blue Proxy tag appears only when a cache or Library proxy is available, including if preparation finishes while Review is open. X dims an excluded row but keeps it visible; the control becomes a dash that restores the row when clicked, without changing Skip. Confirming Commit authorizes replacement for included Update rows. Changed source/destination state invalidates review; a later conflict fails the affected entry for a fresh review. Existing source/thumbnail assets with a different extension block processing to avoid ambiguous roles.

The backend captures immutable in-memory clip snapshots and locks submitted clips until completion, cancellation, or failure. One encoder and one transfer worker can run concurrently. Ready submitted clips transfer first while others wait for proxies; submission raises their encoding priority. A background encode below 20% is cancelled to make way for a submitted clip that needs a proxy, then restarts later. Encodes at or above 20%, submitted encodes, and final publication finish first. State is pushed through backend/main/preload notifications without status polling. The centred footer shows pending proxy/commit counts (for example, `1 proxy, 2 commits`) omitting categories with no queued/active work, and is empty when idle. There is no aggregate progress bar; thumbnail bars show each operation's progress. The toolbar Stop control cancels all generation and Library sync work; the footer has no cancellation control. Individual cards carry activity details: discovering clips show a thumbnail shimmer and stay locked until metadata/thumbnail preparation finishes; editable cards remain unlocked during background encoding; queued cards are dimmed and gently pulse; active transfers show a centered spinner over dimmed media. Synced cards have prominent green backgrounds and changed cards yellow backgrounds, with matching green/yellow outlines only when selected, and skipped cards nearly black with heavily darkened thumbnails, muted filenames, and a deep red SKIP ribbon across the thumbnail’s top-left corner while remaining editable. Other card states have no visible icons or text badges. The top-left proxy indicator is hollow white until a proxy location is known, yellow for Cache, green for Library, and hidden on skipped clips. Encoding and transfer use matching 6px yellow/green spinners over gently darkened thumbnails; transfers take precedence. A 6 px, undimmed progress bar along the thumbnail’s bottom edge is yellow for proxy encoding and green for Library sync, without visible numbers; transfer progress takes precedence if both are reported. Hover text and accessible labels explain activity and errors. Yellow card styling describes a pending Library update (including a missing proxy), independently of background encoding. Animation respects reduced-motion preferences.

Successful processing publishes JSON and saves a local receipt for that Library, attributes, and thumbnail content. Synced requires matching attributes/thumbnail plus one source, thumbnail, metadata JSON, and proxy in the latest Library filename check. Reverted metadata edits can restore Synced; selection and Skip do not affect it. Existing core assets without a matching receipt, or with missing required assets, show Needs Syncing. Fully deleted core assets are New even if an optional proxy remains. Receipts persist normally and through an unavailable share, where their status is unverified. The refresh icon beside Configuration updates filename presence after external edits, without opening media or JSON contents. Revert explicitly reads only selected metadata and thumbnail files. Library asset listings are not polled, and no full-file integrity pass is performed.

### Proxy preparation and cache

The app manages its files under `Shot Manager Cache/` in the local app data directory, beside Electron's own `Cache/`. Use **Browse Cache** in Configuration to open it in Finder. It contains `metadata.json`, `thumbnails/`, `fingerprints/`, and `proxies/`. The new Cache starts empty; existing files in the former shared `Cache/`, older `owmo-shot-manager/`, and previously user-chosen Cache locations remain untouched. The Library location remains user-configured and pending until Save; Cancel, closing, or Escape discards a pending choice. Completed files use `proxies/<id>.proxy.mov`; unique `.partial` files stay unpublished until FFmpeg succeeds. Proxy preparation starts automatically for available, non-skipped discovered clips after the Library presence check establishes that a proxy is missing. Completed cache files are reused across renderer/app restarts. One lower-priority encoder starts after thumbnail work is caught up, with bounded decoding/encoding threads; thumbnails have their own worker and do not wait behind a full encode.

The preset is ProRes 422 Proxy in MOV, 10-bit 4:2:2, PCM audio preserving source tracks/channels/sample rate, exact source frame timing and available timecode, with no viewing LUT. Scaling preserves displayed aspect ratio and rotation, fits a maximum 1280-pixel long edge, and never upscales; dimensions are codec-compatible and pixels normalized to square. Standard color declarations are preserved where representable. Camera-specific log/gamut declarations remain in Library JSON; unknown/capture-specific names are not falsely tagged Rec.709 or passed as invalid FFmpeg enums. The intended input is locked frame-rate footage; no VFR conversion workflow is added.

An existing regular `<id>.proxy.mov` in the Library is assumed good. Delete it manually and use Refresh to request regeneration. A submitted clip waits for its proxy without blocking ready clips. After all transfers, metadata publication, and receipt persistence succeed, the matching cache proxy is removed. Failures and Stop retain completed cache proxies. Encoding checks free space before starting and during output and pauses before the drive reaches a 512 MiB reserve; cache has no quota. Inactive clip drafts and receipts, thumbnails, valid fingerprint records, and cache proxies expire after 90 days at graceful shutdown. Saved Identity/Project options and corrupt persisted records remain until explicitly cleared. Unfinished files left by an abrupt application/volume failure are ignored until retention cleanup or manual removal. Clear Cache stops background encoding before removing the selected app-owned files; keeping proxies leaves those files available for later reuse.

Rsync preserves source modification times and uses its size/mtime quick check to avoid recopying unchanged videos when metadata changes. Thumbnails are copied from a private temporary snapshot. Library directory listings are shared across each review/submission; execution checks the known target paths. Saving the selected Library records its mounted volume in configuration; older settings require choosing the Library again before processing clips. The destination must already exist, differ from the source folder itself, match that configured volume, and retain its reviewed folder/mount identity. Missing `/Volumes` mounts, symlink assets, and unreviewed target changes are rejected; the app never creates a missing Library root. Option removal and cache clearing are blocked while clips are queued. Folder discovery can continue, and Eject cancels selected clip jobs before removing their records. Changing the configured Library is also blocked while processing is active.

The toolbar control immediately left of Configuration shows **Refresh** when idle/paused and a neutral **Stop** square while either queue has work. Refresh checks Library and cache presence, then resumes missing thumbnail/proxy preparation; it never resubmits cancelled Library transfers. It is disabled while checking. Stop all work confirms before cancelling rsync/FFmpeg work, clearing waiting submissions/generation, and suspending automatic queueing. A stop during a presence check prevents its completion from restarting workers. Pending proxy/commit counts appear during work, with no footer X. Toolbar Stop cancels all queued and active work; card/inspector Stop cancels individual Commits. Completed Library clips remain synced; cancelled submissions unlock and preserve receipts/pending changes. Completed cache proxies remain reusable. Clicking Commit refreshes Library/cache presence and resumes required preparation before review; transfers start only after confirmation. A late Commit review cannot restart work after Stop. Ordinary metadata editing remains available for prepared, unsubmitted clips. Failures show clip/error details, unlock/remove failed submissions, and allow remaining ready clips to continue. A later explicit Commit/Refresh can retry proxies. Library orphan cleanup and durable recovery remain deferred.

The queue survives renderer reloads, but is not persisted across application crashes/restarts. Graceful shutdown stops transfers before closing the backend. Only the usual drafts and successful processing receipts persist; there is no durable queue journal or automatic resume. A crash between Library publication and receipt persistence can leave a processed Library shot without a local checkmark; it will appear as Update in a subsequent review.

Library browsing/editing and its disposable local catalog remain future work. The existing JSON contract and reserved asset names live in `shared/library.ts`. Presence discovery streams the flat directory into a per-clip index; review/submission share each listing and inspect only their selected target files. A slow refresh preserves Commits completed during that scan. The future catalog should be separate from Import's workspace/drafts: refresh remote JSON with bounded concurrency, search/filter locally, and load thumbnails on demand. Catalog invalidation/offline behavior and editing destinations/layouts need discussion before implementation. Local scale checks do not establish SMB performance. Real NAS reads/writes require explicit authorization for that operation.

## Development

The app uses Electron and React in `desktop/` and `client/`, a local Fastify backend in `server/`, and shared types in `shared/`. The renderer accesses files through restricted preload/backend interfaces. The backend runs in a separate Electron utility process.

Clip attribute keys are `identity`, `project`, `scene`, `notes`, and `tags`: Identity/Project are nullable single values, Scene/Notes are text, and Tags is a list. The independent `skipped` boolean persists with the draft, defaults to false, and is preserved by Clear. Older `projects`/`context` records migrate atomically to `project`/`tags`, with prior multiple-project assignments retained in recovery metadata. Scene and Notes have separate debounce keys and share the main-process save/retry/quit handling.

IPC carries structured error data so messages, codes, HTTP status, and unknown mutation outcomes survive the preload boundary. Backend reads have a 15-second deadline; mutations wait for a response. A lost mutation response is reported as an unknown outcome, rather than claiming cancellation. Only the existing idempotent clip-attribute commands are retained for explicit ordered retry; processing submissions are not automatically retried. If a submission response is lost, the UI checks current queue status instead of assuming nothing was queued.

Workspace ownership lives in `server/scanner.ts`; `server/workspace.ts` accepts temporary ID/path discovery requests and monitors referenced directories. There is no Source registry or source-level rescan/remove/relink API. Rediscovery is additive and never removes or locks existing cards. Commit uses eligible selected clips, or all eligible clips when nothing is selected; an ineligible selection never falls back to everything. Accepted submissions append immutable snapshots, retain progress history, and reject stale/conflicting additions independently. Per-clip Stop retains/unlocks cards; Eject removes unqueued clips; toolbar Stop cancels all work. Successful publication retains its receipt even if cancellation races with completion.

Workspace snapshots return cached state without touching media. Backend monitoring checks each unique clip-containing directory every five seconds and revalidates affected files when a missing directory returns. Routine checks do not enumerate contents, inspect every video, detect mounted volumes, or poll the folder originally selected. Unavailable directory members are flagged together, with one consolidated path/count dialog per outage offering Eject affected clips. Cached information remains editable. Recovery respects a manual Stop; unavailable queued media follows the existing failure/removal policy, with Commit needed to resubmit. Monitoring references disappear with the final workspace member. Individual file access validates the stored absolute path and file identity. Change events carry revision notices instead of collections. The renderer coalesces notices over 250 ms and permits one snapshot request at a time; vocabulary has its own revision so preview, Notes, and Skip changes do not reload suggestions.

Clear Cache restarts the backend and reloads the workspace so snapshot revision counters reset together. The navigation guard permits reloading the current app URL while blocking navigation to other URLs.

Clip-attribute edits still save atomically before acknowledgment. Scan-only bookkeeping is batched in groups of up to 64 records and flushed on scan completion and graceful shutdown. An abrupt process exit can lose the latest bookkeeping batch, while acknowledged attribute edits remain saved.
